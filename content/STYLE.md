# 코어무드 저널 · 페이지 작성 가이드

코어무드 홈페이지의 모든 글(저널, 업종별 페이지, FAQ)은 이 문서를 기준으로 씁니다.
사람이 직접 쓴 것처럼 읽혀야 하고, 읽은 사람이 "이 팀은 현장을 안다"고 느껴야 합니다.

---

## 1. 누가, 누구에게 쓰는 글인가

- **화자**: 10여 년간 상업공간을 기획하고 시공해 온 코어무드 실무자.
- **독자**: 첫 매장을 준비하는 창업자, 2호점·리뉴얼을 고민하는 운영자, 공실을 줄여야 하는 건물주, 사무실을 옮기는 기업 담당자.
- **목표**: 독자가 글 하나로 실제 판단을 한 가지라도 더 잘하게 만드는 것. 그 과정에서 코어무드가 어떤 기준으로 일하는지 자연스럽게 드러나는 것.

## 2. 문체

- 합니다체를 씁니다. 단정하되 과장하지 않습니다. 친절하되 아첨하지 않습니다.
- 장면으로 설명합니다. "동선이 중요합니다"보다 "점심 피크에 주문 줄과 픽업 줄이 한곳에서 엉키면 직원이 카운터를 세 번 돌아 나옵니다"가 낫습니다.
- 문장 길이를 섞습니다. 짧은 문장으로 끊고, 필요한 곳에서만 길게 풉니다.
- 현장의 말을 씁니다. 철거, 목공, 설비, 전기 증설, 실측, 조닝, 색온도, 조도, 마감재처럼 실무 용어를 쓰되 처음 나올 때 한 번 풀어 줍니다.
- 판단 기준을 줍니다. "이럴 때는 A, 저럴 때는 B"처럼 독자가 자기 상황에 대입할 수 있게 씁니다.
- 반대 의견이나 예외도 짚습니다. "모든 매장에 맞는 정답은 아닙니다"라고 말할 수 있어야 신뢰가 생깁니다.

### 쓰지 않는 표현 (AI 번역투·상투구)

| 쓰지 않음 | 대신 |
|---|---|
| ~에 대해 알아보겠습니다 / 살펴보겠습니다 / 알아볼까요? | 바로 본론으로 들어갑니다 |
| 결론적으로, 요약하자면, 마지막으로 정리하면 | 마지막 소제목에서 자연스럽게 마무리 |
| 다양한, 효과적인, 혁신적인, 최적의, 완벽한 | 무엇이 어떻게 다른지 구체적으로 |
| ~하는 것이 중요합니다 (반복) | 왜 중요한지를 장면으로 |
| ~에 있어서, ~함에 있어, ~를 가지고 있다 | 우리말 어순으로 바꿔 씁니다 |
| 여러분, 사장님들! | 2인칭은 꼭 필요할 때 "~하신다면" 정도로 |
| 도움이 되셨길 바랍니다 / 성공을 응원합니다 | 다음에 할 일 한 가지를 제안하고 끝냅니다 |
| 이모지, 느낌표, 과한 줄표(—) | 쓰지 않습니다 |
| 모든 소제목을 질문형으로 | 질문형 소제목은 글 하나에 한두 개까지 |
| 항목을 늘 세 개씩 나열 | 실제로 필요한 개수만큼 |

## 3. 브랜드 표기 규칙 (반드시 지킴)

- 회사명은 **코어무드**(영문 CORE MOOD, CoreMood)로 씁니다. 법인명 (주)블랭크는 푸터에만 있고 본문에는 쓰지 않습니다.
- 이전 법인명이나 다른 브랜드명은 쓰지 않습니다.
- 실적 수치는 **"10여 년간 340개 이상 프로젝트"** 형태로만 씁니다. 다른 누적 수치를 만들어 내지 않습니다.
- **최상급 표현 금지**: 최고, 1위, 넘버원, 최초, 유일, 업계 최저가 등.
- **보장 표현 금지**: 매출 보장, 수익 보장, 100% 만족, 무조건, 반드시 성공 등. 인테리어가 매출을 "결정한다", "올려 준다"고 단정하지 않습니다. "판단에 영향을 준다", "줄일 수 있는 위험" 정도로 씁니다.
- **인허가·소방·전기 용량** 같은 항목은 구체 조건을 단정하지 않고 **"별도 확인 절차를 안내해 드립니다"**, **"관할 기관 확인이 필요한 별도 확인 항목입니다"** 식으로 씁니다. 법 조문 번호, 면적 기준, 과태료 금액 같은 수치를 적지 않습니다.
- **수치를 지어내지 않습니다.** 통계, 설문 결과, 비율, 고객 사례의 금액·매출 변화를 만들어 쓰지 않습니다. 확인되지 않은 고객 후기나 실명 사례도 쓰지 않습니다.
- 금액을 말해야 할 때는 코어무드 [견적 안내](/estimate) 페이지의 개략 기준만 인용합니다.
  - 마감 사양별 평당 단가(만 원): 에센셜 70 · 베이직 110 · 스탠다드 170 · 프리미엄 220 · 시그니처 280(협의)
  - 업종 계수(카페=1.00): 숙박 1.35 · 바/라운지 1.28 · 음식점 1.10 · 리테일 1.04 · 미용 0.96 · 파티룸/스튜디오 0.90 · 오피스 0.86 · 스터디카페/학원 0.82
  - 이 기준을 쓸 때는 "부가세, 가구·집기, 인허가 비용 별도 · 현장 실측 후 확정"을 함께 적습니다.
- 공사 기간처럼 일반적인 범위를 말할 때는 "규모와 공정에 따라 다르지만" 같은 조건을 붙이고, 단정하지 않습니다.

## 4. 글 구조 (저널)

1. **도입 (2~3문단)**: 독자가 겪는 구체적인 상황으로 시작합니다. 첫 문단 안에 핵심 키워드를 자연스럽게 한 번 넣습니다.
2. **본문 소제목(##) 4~7개**: 소제목만 읽어도 글의 흐름이 보여야 합니다. 핵심 키워드는 소제목 하나에 자연스럽게 들어가면 충분합니다.
3. **실무 도구 1개 이상**: 체크리스트(:::check), 비교표, 단계별 순서 중 하나.
4. **코어무드의 방식**: 본문 중 한 번, 광고처럼 보이지 않게 "코어무드는 이 단계에서 ~를 먼저 확인합니다" 정도로 언급합니다.
5. **마무리 소제목**: 정리 대신 독자가 오늘 할 수 있는 다음 행동 한 가지. 관련 페이지(견적 안내, 업종별 페이지, 상담 신청) 링크 1개.

- 분량: 본문 **3,000~5,000자**(공백 포함). 짧고 얕은 글보다 길어도 끝까지 읽히는 글을 씁니다.
- 내부 링크: **3~5개**. 업종별 페이지(/industries/...), 서비스(/services), 견적 안내(/estimate), 진행 절차(/process), 다른 저널 글(/journal/...).
- 외부 링크는 꼭 필요할 때만(공공기관 안내 페이지 등) 씁니다.

## 5. SEO 기준

- **제목(title)**: 25~40자. 핵심 키워드를 앞쪽에. 낚시성 표현 금지.
- **설명(description)**: 80~150자. 글을 읽으면 무엇을 판단할 수 있는지 한 문장으로.
- **키워드(keyword)**: 사람들이 실제로 검색하는 말 하나. (예: 카페 인테리어 비용, 미용실 인테리어, 네이버 플레이스 등록)
- **태그(tags)**: 2~5개. 업종별 페이지와 연결되는 말을 포함합니다(카페, 미용실, 파티룸, 스터디카페, 숙박, 음식점, 바, 오피스, 리테일, 스튜디오).
- 키워드를 억지로 반복하지 않습니다. 같은 뜻의 다른 말(상가 인테리어 / 매장 인테리어 / 상업공간 인테리어)을 섞어 씁니다.
- 이미지 alt는 이미지에 실제로 보이는 것을 씁니다.

## 6. 파일 형식

저널 글은 `content/posts/<slug>.md`, 업종 페이지는 `content/industries/<slug>.md` 입니다.

```
---
title: 상가 인테리어 비용, 평당 단가만 보면 안 되는 이유
slug: commercial-interior-cost-guide
date: 2026-10-26T10:00:00+09:00
category: interior
keyword: 상가 인테리어 비용
tags: [상가 인테리어, 인테리어 비용, 견적서]
description: 평당 단가가 같아도 최종 금액이 크게 달라지는 이유를 철거, 설비, 전기, 간판, 가구 항목별로 정리했습니다. 견적을 받기 전에 확인할 기준을 알려 드립니다.
cover: /assets/img/es-hero.webp
coverAlt: 따뜻한 조명의 쇼룸 인테리어
draft: false
---
본문(마크다운)
```

- `slug`: 영문 소문자, 숫자, 하이픈만. 파일 이름과 같게.
- `category`: `branding`(브랜딩) · `interior`(인테리어) · `marketing`(마케팅) · `startup`(창업) · `business`(공간 비즈니스)
- `cover`: `data/images.json` 에 있는 이미지 경로 중 내용과 맞는 것.
- `date`: 발행 시각. 미래 시각이면 그 시각 이후 빌드에서 공개됩니다(예약 발행).
- `draft: true` 면 공개되지 않습니다.

### 본문 마크다운 문법

- 소제목은 `##`, `###` 만 씁니다. (`#` 은 제목 전용이라 본문에서 쓰지 않음)
- 일반 문법: 문단, `- 목록`, `1. 번호 목록`, `> 인용`, `**굵게**`, `[링크](/estimate)`, 표(`| a | b |`), 이미지 `![설명](/assets/img/x.webp "캡션")`
- 전용 블록:

```
:::note 현장에서 자주 놓치는 것
설명 문단
:::

:::check 계약 전 체크리스트
- 확인할 항목 1
- 확인할 항목 2
:::

:::spec
업종: 카페
면적: 20~40평
기간: 4~6주
범위: 컨셉 · 설계 · 시공
:::

:::faq
Q. 질문
답변 문단

Q. 다음 질문
답변 문단
:::
```

- `:::spec` 은 도면 타이틀블록 모양으로 표시되는 요약표입니다(2~4줄).
- `:::faq` 는 아코디언과 검색엔진용 FAQ 구조화 데이터로 함께 출력됩니다. 업종 페이지에는 4~6문항, 저널 글에는 필요할 때 2~4문항.

## 7. 발행 전 점검

`node scripts/check.js` 를 실행해 오류가 없어야 합니다. 금지 표현, 필수 항목, 분량, 내부 링크 경로를 자동으로 확인합니다.
